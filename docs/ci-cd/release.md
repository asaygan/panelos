# Release

PanelOS uses **Changesets** to drive semver bumps and `CHANGELOG.md` entries. Web and API release independently.

## Versioning

- **SemVer** (MAJOR.MINOR.PATCH).
- Two release trains:
  - `web-vX.Y.Z` — frontend
  - `api-vX.Y.Z` — backend
- `packages/types` follows the API train.

## Tag conventions

```
api-v1.4.0
web-v1.4.0
```

Tags are immutable. Hot-fixes get a new patch tag, never a re-tag.

## Changesets workflow

1. Author runs `pnpm changeset` and selects affected packages + bump level.
2. A `.changeset/<random>.md` file is committed with the PR.
3. On merge to `main`, the release workflow opens a "Version Packages" PR.
4. Reviewer merges the Version Packages PR.
5. Release workflow tags + pushes the tags + appends to `CHANGELOG.md`.
6. `cd-web.yml` / `cd-api.yml` deploy the new tag to production.

## What counts as MAJOR

- API: removing or renaming an endpoint, removing a field from a response, changing a response semantic.
- Web: removing a major surface (e.g., the labels screen).
- Both: changing an env var default that breaks existing deploys.

## What counts as MINOR

- Additive endpoints or fields.
- New screens.
- New optional config.

## What counts as PATCH

- Bug fixes.
- Performance improvements.
- Doc updates that ship with code.

## CHANGELOG

`CHANGELOG.md` per app (`apps/web/CHANGELOG.md`, `apps/api/CHANGELOG.md`). Aggregated `CHANGELOG.md` at repo root for marketing.

## Release notes

Generated by Changesets but edited for tone before publishing. Posted to `#releases` Slack and to Statuspage as "Scheduled maintenance — successful deploy" when the deploy was zero-downtime.

## Co-deploy scenarios

When a change requires API and Web to ship together (rare; we strive for backwards-compatible APIs):

1. Author flags the PR `co-deploy`.
2. Release process tags both `api-vX.Y.Z` and `web-vX.Y.Z` in the same Version Packages PR.
3. Deploys happen API-first, then Web.

## Hotfix

For Sev-1 fixes:

1. Branch from the last prod tag: `git checkout -b hotfix/<scope> api-vX.Y.Z`.
2. Apply fix + tests.
3. Open PR to `main`; once green, cherry-pick to a `hotfix-X.Y.(Z+1)` branch, tag, deploy.
